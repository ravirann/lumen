# Lumen v0.18.1

This patch fixes false “Cluster network unavailable” errors when a reachable
cluster takes longer to return its inventory, particularly over a VPN.

## Fixes

- Enable gzip for Kubernetes API responses, while honoring kubeconfig's
  `disable-compression` setting.
- Give connection establishment and the version request their own eight-second
  deadline. Inventory reads have separate twenty-second deadlines, so a slow
  resource list cannot turn a successful connection into an unreachable cluster.
- Keep clusters accessible when inventory is incomplete. Show a warning naming
  the unavailable resource types and omit incomplete statistics from fleet
  totals instead of displaying healthy zero counts. Reconnect to refresh them.
- Preserve connection failures for invalid credentials and unreachable endpoints.

## Other changes since v0.18.0

Includes the already-merged custom-resource instance management and local Helm
repository management, an Inter font update, and a rustls security update.

## Upgrade and validation

No kubeconfig or cluster changes are required. Update Lumen and reconnect the
cluster. Regression coverage exercises compressed responses, slow inventory,
recovery, authentication failures, and connection timeouts.

The release pipeline checks frontend and Rust tests, dependency and secret scans,
CodeQL, isolated Kubernetes integration, platform builds, and the updater asset
manifest for the release commit. These checks do not establish fresh-install or
upgrade coverage on every operating system.

macOS Apple Silicon and Intel DMGs, Linux x86-64 AppImage/DEB/RPM, and Windows x64
NSIS/MSI installers are available in the release assets. Verify downloads against
the SHA-256 digests in the asset list.

## Signing and known limits

The macOS and Windows binaries remain preview builds with the existing signing
limitations: macOS uses ad-hoc signing without Developer ID notarization; Windows
installers are not Authenticode signed. Tauri updater signatures are separate
from operating-system signing. Existing upstream dependency audit warnings remain
tracked. Metrics-server availability is optional and shown as unavailable when
it cannot be queried.
